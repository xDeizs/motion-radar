# Motion Radar — исследование для Motion Studio

Проверено: 2026-11-02. Это отобранный проверяемый набор, не «весь интернет» и не рейтинг по несопоставимым просмотрам.

## Главный вывод

Claude — часть производства, а не вся студия. Надёжная цепочка: бриф → стиль → storyboard → scene specs → кодовые сцены → повторяемый seek → кадры/animatic → звук → QA → экспорт. Существующий HTML+seek(t) движок оставляем основой; Remotion/HyperFrames — варианты под конкретную задачу, не обязательная миграция.

## Что действительно проверено

Тексты и код не равны просмотру видео. У каждой карточки ниже явно указан объём проверки. YouTube заблокировал анонимное получение субтитров; не использовались cookies, обходы и смена аккаунтов. Instagram — только caption. Скрипты и плагины авторов автоматически не устанавливались.

## Конкретная находка в исходниках

Репозиторий whaleyxbt/claude-motion, commit `e627941543d9988b155dc610bb9cc0115a5e365e`. В `sims/kit/director.js` `pre(t)` читает сохранённый `foci`, который обновляется лишь в `post(t, info)`. Изолированный тест модуля с DOM/stage stubs, sequence `0 → 1 → 2 → 1`, получил x фокуса в t=1: **100**, затем **200**. Это подтверждённая зависимость выбора crop от предыдущего вызова при динамических foci. Не pixel-тест всей сцены, не утверждение о дефекте каждого ролика. Предложение: focusAt(t) до pre/crop или одинаковый подготовительный проход; затем A→B→A и random-order frame test. Production студии не менялся.

Локальные доказательства: `research/director-audit.json` и `research/check-director.cjs`; исходный модуль для воспроизведения скачивается только с закреплённого commit после просмотра. Скрипт теста не скачивает и не исполняет сторонние зависимости.

## Бесплатно и коммерчески

Берём легально открытые тексты/код. Не скачиваем платные курсы из сливов. «Открытый tutorial» не означает бесплатный Claude, генераторы речи, облачный render или лицензию любого размера компании. Remotion source-available, не OSI open source; см. FAQ ниже. Для публичного Radar — ссылка, атрибуция и короткая собственная выжимка, не копия полного поста/видео.

### Разбор кода: кадр, таймлайн, review-loop

Автор / площадка: whaleyxbt · GitHub
Источник: https://github.com/whaleyxbt/claude-motion
Объём: прочитаны выбранные исходники + изолированный тест

Прочитаны runtime, capture, director, engine/main, engine/timeline и review-loop на закреплённом коммите. Найден конкретный риск зависимости кадра от предыдущего вызова.

- capture.mjs вызывает render(from + i / fps), снимает кадр и пишет его в FFmpeg.
- runtime отключает live-loop в capture-режиме и ждёт шрифты перед setup.
- engine/main вычисляет камеру, детали и shader uniforms из t; звук и сцены используют timeline.
- Важно: director.pre берёт foci прошлого post. Изолированный тест 0→1→2→1 дал разные x фокуса в t=1: 100 и 200. Для динамических foci это нарушает независимость seek.
- Перед переносом: вычислять focusAt(t) до crop либо делать одинаковый подготовительный проход для каждого кадра; затем проверить A→B→A.

**Ограничения:** Тест запускал только прочитанный director в VM с макетами DOM/stage, без сети. Это не pixel-тест всей 3D-сцены. Не все сцены затронуты. Остальной репозиторий полностью не аудирован. В студии уже есть карточка этого проекта — подготовлено дополнение, не дубликат установки.

**Доступ:** MIT для этого репозитория; Remotion, медиа и сервисы имеют отдельные условия.

- runtime.js · закреплённая версия: https://github.com/whaleyxbt/claude-motion/blob/e627941543d9988b155dc610bb9cc0115a5e365e/sims/kit/runtime.js
- capture.mjs: https://github.com/whaleyxbt/claude-motion/blob/e627941543d9988b155dc610bb9cc0115a5e365e/sims/capture.mjs
- director.js: https://github.com/whaleyxbt/claude-motion/blob/e627941543d9988b155dc610bb9cc0115a5e365e/sims/kit/director.js

## Как это учит студию

Не fine-tuning и не автоматическое исполнение постов. Intake → source/rights check → карточка техники → sandbox example → QA/regression → явное одобрение → knowledge index и retrieval. Плохие советы остаются гипотезами; нельзя превращать их в lint rule без собственного подтверждённого сбоя.

Первый практический набор: 1) договор seek, 2) scene spec и component registry, 3) покадровый reverse engineering разрешённых референсов, 4) frame review с timestamp, 5) отдельные права на код, медиа и модели.

Материалы для существующей студии лежат в `studio-bridge/`. Они подготовлены к проверке, не импортированы в production knowledge/cards. Индексы вручную не редактируются.
