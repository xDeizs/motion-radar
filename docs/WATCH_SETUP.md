## Запуск без сторонних Python-пакетов

Нужен Python 3.11+ (workflow использует 3.12). Новые пакеты и browsers на ПК автоматически не устанавливаются.

```bash
python scripts/watch_sources.py
python scripts/watch_sources.py --offline
python scripts/export_studio.py
```

Обычно без `--force`: успешные ответы кэшируются минимум 30 минут, ошибки — с паузой; 401/403/429 приостанавливают origin. Уважать Retry-After. `--force` только для осознанной диагностики после исправления, не для обхода квот. `--offline` не идёт в сеть. Сборщик не читает ключи и не вызывает LLM.

Конфигурация — `config/watchlist.json`. Ограничения: максимум 16 записей, 5 элементов на источник, body до 2 MB, timeout 25 sec, только проверенные HTTPS origins и типизированные endpoint-параметры. Redirects запрещены. Новый RSS-домен требует review allowlist в коде. Полученные ссылки не открываются и команды из контента не исполняются. Названия/строки экранируются при выводе в HTML. Нет автоскачивания видео/кода/ассетов.

На успешном обновлении источник заменяет свой снимок текущими 5 элементами; при ошибке сохраняется прошлый со `source_stale`. Это не полная история и не сервис отслеживания удалённых постов. URL даёт стабильный ID; повторный запуск не дублирует сигнал. Заголовки могут изменяться. `seen_at` сохраняется для повторно найденного URL.

## Публикация

1. Подтвердить собственный GitHub-репозиторий и ветку. Не отправлять код в неподтверждённый репозиторий.
2. Загрузить исходники без `.private/`, `.env*`, cookies и клиентских материалов.
3. Включить GitHub Pages через Actions и проверить первый `workflow_dispatch`.
4. Проверить job logs, `data/signals.json`, публичную страницу и реальные даты проверок.
5. В этом workflow лёгкий watch запланирован каждые 30 минут, полный RSS/GitHub discovery — раз в 6 часов. GitHub cron может задерживаться или отключаться; не обещать «сразу» и не продавать SLA до измерений. Возможны лимиты Actions/hosting аккаунта. Если нужен гарантированно малый lag — отдельный постоянно работающий backend + webhook/queue, а не статический HTML.

## Права и подключения

- **YouTube**: публичный channel Atom feed даёт ограниченные metadata. Для near-real-time official PubSubHubbub нужны серверный callback и подтверждённая подписка; здесь не развёрнуты. Data API captions не даёт универсального права скачать любой транскрипт. Не публиковать чужие субтитры/ролики автоматически. https://developers.google.com/youtube/v3/guides/push_notifications
- **X**: нужны свой API-доступ и проверка цен/политики отображения, author IDs/rules, разрешённый webhook/stream или ограниченный poll, dedup, edit/delete handling. Эти account-specific настройки не выполнены. https://docs.x.com/x-api/webhooks/stream/introduction
- **Reddit**: одобренный use case, OAuth, лимиты и политика удаления/обновления. Не считать обычную видимость страницы разрешением коммерчески зеркалировать весь контент. https://support.reddithelp.com/hc/en-us/articles/14945211791892-Reddit-Data-API-Access
- **Instagram**: professional API имеет account/use-case ограничения; не обещает чтение всего чужого Instagram. Сначала разрешённый сценарий и OAuth. https://developers.facebook.com/documentation/instagram-platform/overview
- **Публичный Radar**: атрибуция, ссылка и короткая собственная аннотация. Full-post mirror, copyrighted media, клиентские брифы и private API queues не публикуются. Лицензии кода, шрифтов, музыки, голосов и коммерческого output проверяются раздельно.

## Как Radar помогает студии

Intake → URL dedup → scope/rights → очередь исследования → авторская карточка → маленький sandbox example → render/QA → human approval → knowledge index.

Это retrieval/playbooks/регрессионные тесты, не переобучение весов модели. Интернет-тексты не становятся системными инструкциями. Экспорт **не выполняется автоматически** агентом студии и не меняет его стили.

`python scripts/export_studio.py` создаёт новый пакет в `.private/studio-export/`. В нём исследовательские карточки, metadata-сигналы с флагом needs_review и manifest SHA-256. Затем прочитать пакет в студии через существующий inbox-sort workflow; соблюсти её ограничения, не менять `styles/` и не писать generated indexes вручную. Никакой новый lint rule не вводится по совету автора без собственного подтверждённого сбоя.
